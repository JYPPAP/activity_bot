# 0004. 활동 세션은 메모리 추적과 주기적 DB 체크포인트를 병행

- **상태**: Accepted
- **날짜**: 2026-09-22
- **의사결정자**: activity_bot maintainers
- **관련**: [`ActivityTracker`](../../src/services/ActivityTracker.js), [이벤트 흐름](../12-event-flow.md)

## 컨텍스트 (Context)

음성 활동 시간을 모든 입·퇴장 로그로 보관해 사후 집계하면 메모리와 저장소가 계속 커지고 계산도 복잡해진다. 반대로 진행 중 세션을 메모리에만 두면 Termux의 비정상 종료나 Discord 재연결 때 아직 종료되지 않은 구간을 잃을 수 있다.

## 검토한 옵션 (Options)

### 옵션 1: 입·퇴장 이벤트 로그를 영구 저장하고 사후 집계
- 장점: 원시 이벤트를 재처리할 수 있다.
- 단점: 중간 데이터와 집계 로직이 커지고 저장·조회 비용이 증가한다.

### 옵션 2: 활성 세션만 메모리에 저장하고 퇴장 때 기록
- 장점: 구조가 단순하고 메모리 사용량이 동시 접속자 수에 비례한다.
- 단점: 프로세스가 강제 종료되면 마지막 세션 구간을 잃는다.

### 옵션 3: 활성 세션은 메모리에서 추적하되 주기적으로 DB에 체크포인트
- 장점: 메모리 크기를 제한하면서 비정상 종료 시 손실 구간을 줄인다.
- 단점: 체크포인트 저장과 세션 시작 시각 재설정이 원자적으로 유지되어야 한다.

## 결정 (Decision)

**현재 활성 세션만 `activeSessions`에 보관하고, 퇴장 시 즉시 저장하며 10분마다 진행 중 구간을 DB에 체크포인트한다.**

## 근거 (Rationale)

- 완료된 구간은 월별 활동 테이블에 바로 누적하므로 별도 `activity_logs` 집계가 필요 없다.
- 체크포인트 성공 후 세션 시작 시각을 현재 시각으로 옮겨 같은 구간의 중복 합산을 피한다.
- 시작·재연결 시 실제 길드 음성 상태를 스캔해 세션을 재구성하고, 제외 채널 및 관전·대기 사용자는 추적하지 않는다.
- 30분마다 실제 음성 상태와 대조하고 8시간 이상 세션을 재검증해 고아 세션을 정리한다.

## 결과 (Consequences)

- 긍정적: 메모리 사용량이 활성 사용자 수에 제한되고, 강제 종료 시 손실 범위가 체크포인트 간격 이내로 줄어든다.
- 부정적: 재시작 전에 저장되지 않은 구간의 정확한 입장 시각은 복원할 수 없어 재시작 시각부터 새 세션으로 취급한다.
- 추후 재검토 조건: 세션 원장이나 초 단위 정산이 필요해지거나 DB 쓰기 빈도가 운영 병목이 될 때.
