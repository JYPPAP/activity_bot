# 개인 가입 채널 운영 안내

신규 회원이 입장하면 설정한 가입 카테고리에 `가입-사용자명-ID뒷자리` 채널을 생성합니다. 일반 회원 중에서는 본인만 볼 수 있고, 봇의 Embed·버튼·선택 메뉴로 가입합니다. 채팅 및 스레드 작성은 차단됩니다. Discord Administrator 권한 사용자는 비공개 채널도 볼 수 있습니다.

## 배포

Termux의 봇 저장소에서 순서대로 실행합니다.

```bash
npm run backup:db
git pull
npm run migrate:up
npm run register
pm2 restart discord-bot
pm2 logs discord-bot --lines 100
```

개인 채널 전환 마이그레이션(`20261011000001`)은 이전 단계별 채널 설정을 비활성화하므로 새 설정이 필요합니다. 규칙 문서 마이그레이션(`20261011000002`)은 개인 채널 설정을 유지하고 문서 순서·버전 컬럼만 추가합니다. 기존 게임 목록과 진행 상태, 기존 단계별 채널·메시지는 보존하며 자동 삭제하지 않습니다. 이전 회원은 시작 버튼으로 저장된 단계부터 이어갈 수 있으며 규칙 문서가 변경되면 다시 동의합니다.

## 서버 권한 준비

1. `가입 안내` 카테고리를 준비합니다. 봇은 이 카테고리에서 채널 보기·메시지 보내기·Embed 링크·메시지 기록 보기·채널 관리 권한이 있어야 합니다. 봇은 카테고리 권한을 변경하지 않고 개인 채널마다 본인·봇 접근 권한을 명시합니다.
2. 비공개 텍스트 채널 `가입-심사`를 준비합니다. `@everyone`과 모든 일반 역할·일반 사용자에게 채널이 보이지 않아야 합니다. 봇에게는 채널 보기·메시지 보내기·Embed 링크·기록 보기·역할 관리 권한을 줍니다(개인 권한 덮어쓰기 수정에 필요). 봇 자신의 역할로 열람을 허용해도 됩니다. `/가입관리 설정` 실행자 본인은 예외로 허용하고 열람·기록 보기 권한을 자동 부여하며 심사 담당자로 저장합니다. 본인은 Administrator 권한 없이 승인·거절할 수 있습니다. 다른 일반 역할/사용자에게 열람이 허용되어 있으면 설정 명령이 거부됩니다. 담당자를 바꿀 때 기존 담당자의 개인 열람 권한을 먼저 제거합니다.
3. 봇 역할의 **서버 권한**으로 채널 관리·역할 관리·채널 보기·메시지 보내기·메시지 기록 보기·Embed 링크·공개 스레드 만들기·비공개 스레드 만들기·스레드에서 메시지 보내기를 부여합니다. 채널 생성 API는 봇이 서버에서 보유한 권한만 허용/거부 설정할 수 있어 스레드 입력 차단에 필요한 권한도 봇이 가지고 있어야 합니다. 채널별 권한만 허용하면 설정이 거부됩니다. 봇 역할을 남성·여성·게임·대기·정회원 역할보다 위로 올립니다. 지급 대상 역할은 `@everyone`, 관리자 역할, Discord 연동이 관리하는 역할이 될 수 없습니다. [Discord 채널 생성 API](https://docs.discord.com/developers/resources/guild#create-guild-channel)
4. 고정 온보딩 채널 `1459874768449699861`에서 봇에게 채널 보기·메시지 보내기·Embed 링크·기록 보기·역할 관리 권한을 줍니다. 설정 명령은 이 채널을 일반 회원에게 공개하고 읽기 전용으로 만듭니다. 기존 단계 역할의 열람 차단도 해제합니다.

서버 다른 채널의 접근 제한은 운영자가 정회원 역할 기준으로 설정해야 합니다. 이 명령은 다른 채널의 기존 접근 권한을 자동 변경하지 않습니다.

## 가입 설정

`사장` 역할 또는 `DEV_ID` 사용자로 실행합니다. 심사채널과 역할 3개는 필수이며 가입카테고리와 규칙은 저장된 설정이나 파일을 사용할 때 생략할 수 있습니다.

| 항목 | 선택/입력 |
|---|---|
| `가입카테고리` | 개인 가입 채널을 생성할 카테고리. 선택 사항, 환경변수 우선 |
| `심사채널` | 설정 실행자 본인·관리자·봇만 보는 텍스트 채널 |
| `남성역할` | 승인 시 부여할 남성 역할 |
| `여성역할` | 승인 시 부여할 여성 역할 |
| `대기역할` | 신청 후 심사 중에 부여할 역할 |
| `규칙` | 규칙 파일이 없을 때 사용할 실제 서버 규칙, 1~3500자. 선택 사항 |

```text
/가입관리 설정 가입카테고리:가입 안내 심사채널:가입-심사 남성역할:@남성 여성역할:@여성 대기역할:@가입-대기 규칙:서로 존중해 주세요. 광고·욕설을 금지합니다.
```

정회원 역할은 `1243633748344438855`, 시작 안내 채널은 `1459874768449699861`로 고정입니다. 성별·대기·정회원 역할은 서로 달라야 하며 게임 역할과도 겹칠 수 없습니다. 기존 단계 접근 역할 4개는 새 가입 관리에 사용하지 않습니다. 이전 절차를 이어가는 회원에게 남아 있으면 제거합니다.

카테고리의 적용 순서는 `.env`의 `ONBOARDING_CATEGORY_ID` → 명령어 `가입카테고리` 선택 → 기존 저장 설정입니다. 환경변수가 있으면 명령어에서 다른 카테고리를 선택해도 환경변수 값이 적용됩니다. 환경변수를 변경하면 봇을 재시작합니다. 실제 `.env`는 운영자가 직접 설정하며 예시는 다음과 같습니다.

```dotenv
ONBOARDING_CATEGORY_ID=가입_카테고리_ID
```

## 파일로 서버 규칙 관리

저장소의 `config/onboarding/rules/` 아래 실제 규칙을 `.md` 또는 `.txt` 파일로 작성합니다. `01-기본규칙.md`, `02-활동규칙.md`처럼 번호로 이름을 붙여 순서를 정합니다. 각 파일은 가입 화면의 규칙 페이지 한 장이며 사용자는 순서대로 모든 페이지에 동의합니다. 파일 한 장의 본문은 최대 3500자입니다. `README.md`와 `*.example.md`·`*.example.txt`는 실제 규칙으로 읽지 않으므로 예시를 복사해 실제 이름으로 저장합니다.

실제 규칙 파일이 있으면 파일을 우선 사용합니다. 파일이 없을 때는 `/가입관리 설정 규칙:` 입력 또는 기존 DB의 규칙을 사용합니다. 명령어 입력을 생략하면 기존 DB 규칙을 유지합니다. 파일 내용은 DB fallback에 자동 복사하지 않으므로 파일을 제거할 경우 기존 규칙도 없으면 다시 설정해야 합니다. 빈 파일이나 길이 제한을 초과한 파일은 오류로 안내하며 기존 텍스트로 조용히 대체하지 않습니다.

시작 안내를 확인하려면 `/가입관리 게시`를 실행합니다. 고정 온보딩 채널 `1459874768449699861`의 시작 안내에 규칙·단계 미리보기 버튼이 표시됩니다. 미리보기는 본인에게만 보이는 읽기 전용 화면이며 실제 가입 진행이나 역할을 변경하지 않습니다.

## 게임 등록과 안내 게시

게임을 관리할 때는 옵션 없이 실행하면 본인에게만 보이는 관리 화면이 열립니다.

```text
/가입관리 게임추가
```

`게임 추가` 버튼을 누르고 역할 선택 메뉴에서 지급할 역할을 고른 뒤 입력창에 게임 이름을 적습니다. `일괄 수정` 버튼은 현재 목록을 미리 채운 입력창을 엽니다. 한 줄에 `게임 이름 | 역할 ID`를 작성하며 역할 ID 대신 `<@&역할ID>` 형식의 멘션도 사용할 수 있습니다.

```text
리그 오브 레전드 | 123456789012345678
발로란트 | <@&234567890123456789>
```

입력에서 빠진 게임은 삭제하지 않습니다. 입력한 이름 또는 역할이 기존 항목과 같으면 해당 항목을 대체하고, 새 항목은 추가하여 최대 25개를 유지합니다. 화면을 연 뒤 다른 관리 작업으로 목록이 바뀌면 오래된 일괄 수정은 거부되므로 관리 화면을 다시 열어 입력합니다. 이 기능은 기존 회원에게 지급된 역할을 변경하지 않습니다.

기존 게임 선택지는 유지되며 다음처럼 이름과 역할을 함께 입력하는 방식도 사용할 수 있습니다. 한쪽만 입력하면 함께 입력하거나 옵션 없는 관리 화면을 사용하라는 안내가 표시됩니다.

```text
/가입관리 게임추가 이름:리그 오브 레전드 역할:@롤
/가입관리 게임추가 이름:발로란트 역할:@발로란트
/가입관리 게시
```

게임은 최대 25개입니다. 같은 이름 또는 같은 역할을 등록하면 기존 항목을 대체합니다. 기존에 승인받은 회원의 역할을 일괄 변경하는 명령은 아닙니다. `/게시`는 저장된 시작 안내를 갱신하므로 반복 실행해도 시작 안내가 계속 추가되지 않습니다. 예전 단계별 안내 메시지는 운영자가 필요에 따라 정리합니다.

게임 관리 화면을 적용할 때는 `git pull` → `npm run register` → 봇 재시작을 실행합니다. 이번 게임 관리 화면 변경에 추가 DB 마이그레이션은 없습니다.

기존 회원이 선택했던 게임 역할을 목록에서 제거하거나 성별 역할을 교체하면 저장된 선택이 현재 설정과 달라집니다. 진행 중인 회원은 수정 화면에서 다시 선택해야 합니다. 이미 승인된 회원이 재입장하면 정회원 역할은 복원하고, 저장된 성별·게임 역할 중 현재 설정에서도 유효한 것만 함께 복원합니다. 제거된 역할을 새로운 역할에 임의로 대응시키지는 않습니다.

설정 활성화 직후부터 새 입장 회원의 채널이 자동 생성됩니다. 원활한 첫 진행을 위해 게임 등록과 시작 안내 게시까지 연이어 완료합니다. 게임 미등록 시 사용자에게 관리자 등록 요청 화면이 표시됩니다.

## 사용자 흐름과 정리

성별 → 게임 복수 선택·선택 완료 → 규칙 동의 → 요약 확인·수정 → 가입 신청 순서입니다. 단계 이동 시 이전 Embed를 삭제하고 새 Embed를 표시합니다. 게임 선택 중에는 현재 Embed의 선택 내용만 갱신합니다. 이전/수정 버튼으로 돌아가면 규칙 동의는 해제되어 다시 동의합니다.

화면 제목은 성별 선택·게임 선택·규칙 확인·최종 확인에 단계 번호만 붙입니다. 성별 버튼은 ♂️ 남성(파란색), ♀️ 여성(초록색)이며 Discord에서 지원하는 버튼 스타일을 사용합니다. 게임은 드롭다운에서 여러 개를 선택하고 선택한 목록을 체크 표시로 확인한 뒤 선택 완료를 누릅니다. 별도 체크박스 버튼은 아닙니다.

규칙 화면 상단에는 현재 규칙 순서와 문서 제목을 따로 표시합니다. **동의하고 다음 규칙**을 누르면 다음 문서가 표시되고 마지막 문서에서 **동의하고 최종 확인**을 눌러 가입 내용을 확인합니다. 규칙을 여러 화면으로 나누려면 실제 규칙 파일을 여러 개 작성해야 합니다. 기존 `규칙:규칙 텍스트1` 입력만 있는 경우에는 규칙 한 화면만 표시됩니다.

성별과 게임 선택은 승인 전까지 저장만 합니다. 신청 시 대기 역할을 부여하고 심사 채널에 승인·거절 버튼을 보냅니다. 심사 버튼은 실제 Discord Administrator 또는 저장된 심사 담당자만 사용할 수 있습니다. 담당자는 `/가입관리 설정` 실행 시 실행자 계정으로 등록/갱신됩니다. 기존 설정에 담당자가 없으면 관리자만 처리할 수 있으며 본인 계정으로 설정 명령을 다시 실행해야 예외가 적용됩니다. 승인 시 성별·게임·정회원 역할을 부여하고 대기 역할을 제거합니다. 거절 시 대기 역할을 제거하고 최종 확인·수정 화면으로 돌아갑니다.

승인된 개인 채널은 `닫기` 버튼으로 즉시 삭제하거나 승인 후 10분이 지난 다음 유지보수 주기에서 자동 삭제합니다. 주기는 60초입니다. 탈퇴 시 개인 채널은 삭제하지만 진행 기록은 남습니다. 봇 재시작 후에는 저장된 단계·심사 결정·삭제 예약을 복구합니다.

## Discord에서 확인할 항목

관리자 계정 외에 서로 다른 일반 사용자 계정 A/B로 확인합니다.

- A가 입장하면 개인 채널 하나만 생기는지, A만 볼 수 있고 B는 목록에서도 볼 수 없는지 확인합니다. Administrator에게는 보이는 것이 정상입니다.
- A의 개인 채널에서 채팅·스레드 작성이 차단되고 버튼·게임 메뉴는 사용할 수 있는지 확인합니다.
- 단계 이동 후 새 카드만 남는지, 게임 복수 선택 후 선택 완료로 이동하는지 확인합니다.
- 승인 전 성별·게임·정회원 역할이 부여되지 않는지 확인합니다. 신청 후에는 대기 역할만 부여되어야 합니다.
- 일반 사용자가 심사 채널을 볼 수 없는지, 관리자 권한 없는 등록 담당자만 예외로 열람·승인·거절 가능한지 확인합니다. 승인 시 역할이 부여되고 거절 후 수정·재신청이 가능해야 합니다.
- 시작 / 이어하기를 반복해도 개인 채널이 중복 생성되지 않는지 확인합니다.
- 진행 중 봇을 재시작하고 현재 화면과 선택 내용이 복원되는지 확인합니다.
