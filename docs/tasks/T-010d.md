## 치환 규칙 (T-010a~c와 동일)
- import 경로는 파일 위치에 따라 계산: `src/*.js`(container.js, server.js) → `./config/logger-termux.js`, `src/<dir>/*.js` → `../config/logger-termux.js`. `repositories/ActivityRepository.js`, `repositories/ForumRepository.js`, `server.js`는 이미 import 있음 — 중복 추가 금지.
- 매핑: `console.log/info`→`logger.info`, `console.warn`→`logger.warn`, `console.error`→`logger.error`, `console.debug`→`logger.debug`.
- 두 번째 인자는 반드시 객체: `console.error('msg:', err)` → `logger.error('msg', { error: err.message, stack: err.stack })`; 비객체 값은 `{ value }`로 감쌈; 메시지 끝 `:` 제거.
- 로그 라인 삭제·추가·레벨 변경 금지 (1:1 치환). 주석 처리된 console도 주석 상태로 치환.
- **순환 import 주의**: `logger-termux.js`는 `errsole`, `./env.js`, `sqlite3`만 import하므로 `utils/`·`config/` 파일에서 logger를 import해도 순환 없음. 단 `src/config/env.js`는 대상이 아니므로 건드리지 말 것.

## 수정 요청 (Claude 검토 1차)
치환 자체는 승인. 단, 순수 유틸(`TextProcessor`, `inputValidator`)이 logger를 import하게 되면서 **테스트 실행 시 Errsole 서버가 기동**되어 `EADDRINUSE`/`EnvironmentTeardownError`가 발생한다. 테스트에서 logger를 mock하라:
1. 신규 `tests/setup.js`:
   ```js
   import { vi } from 'vitest';
   vi.mock('../src/config/logger-termux.js', () => ({
     logger: { debug: vi.fn(), info: vi.fn(), warn: vi.fn(), error: vi.fn(), alert: vi.fn() },
     default: {},
   }));
   ```
   (logger 객체의 실제 메서드 목록을 `src/config/logger-termux.js`의 `export const logger`에서 확인해 빠진 메서드가 있으면 추가)
2. 신규 `vitest.config.js`: `export default { test: { setupFiles: ['./tests/setup.js'] } }` (ESM, `defineConfig` 사용 가능)
3. `eslint.config.js`의 `tests/**/*.test.js` 블록 files 를 `tests/**/*.js` 로 넓혀 setup.js도 lint 대상에 포함.
4. 검증: `npm test` 를 **2회 연속** 실행해 `EADDRINUSE`·`EnvironmentTeardownError` 문자열이 출력에 없는지 확인 (`npm test 2>&1 | grep -ciE "EADDRINUSE|Teardown"` → 0). `npm run lint` error 0.
5. 마지막 메시지에 위 grep 결과와 `git diff --stat` 포함. 이 섹션 외 파일은 추가 수정 금지.
