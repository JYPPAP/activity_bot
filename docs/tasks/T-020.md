## 테스트 대상 (각 함수를 먼저 읽고 실제 동작 기준으로 작성)
`src/commands/TeamCommand.js` static 메서드 (클래스만 import, 인스턴스 생성 불필요):
- `makePairKey(a, b)`: 순서 무관 동일 키, 자기 자신, 문자열 정렬 기준
- `extractPairs(teams)`: 2인 팀 → 1페어, 3인 팀 → 3페어, 1인 팀 → 0, 여러 팀 합집합
- `scoreTeams(teams, history)`: history와 겹치는 페어 수(또는 실제 구현의 점수 정의) — 겹침 0 / 일부 / 전부
- `distribute(assignees, teamCount)`: 라운드로빈 배치(7명 3팀 → 3/2/2), 빈 입력, teamCount > 인원
- `shuffle(arr)`: 길이·원소 집합 보존 (순서는 검증 금지), 원본 배열 변형 여부는 구현 확인 후 그에 맞게

`src/utils/formatters.js`:
- `formatTime`: 0, 59초 미만, 분/시간 경계, 큰 값
- `formatKoreanDate`, `formatShortDate`: 고정 Date 입력 → 문자열 (타임존 의존이면 `vi.setSystemTime` 대신 UTC 고정 Date 사용, 결과가 환경 의존이면 todo)
- `cleanRoleName`, `formatParticipantName`, `formatMembersList`(빈 배열/1명/여럿)
- `formatParticipantList`, `formatWaitlist`, `formatParticipantChangeMessage`(joined만/left만/둘 다/둘 다 빈 값)

`src/utils/embedBuilder.js` `EmbedFactory`:
- `splitUsersIntoPages(users, maxFieldLength)`: 빈 배열 → 페이지 수, 한계 초과 시 분할, 각 페이지 문자열 길이 ≤ maxFieldLength
- `createNotificationEmbed(title, description, color)`: `.data.title/description/color` 확인
- `createLogEmbed(message, members, colorCode)`: `.data` 필드 확인
