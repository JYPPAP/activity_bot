## 목표 (한 문장)
`src/utils/SafeInteraction.js`에서 **어디서도 호출되지 않는** static 메서드를 제거하되, 사용 중인 메서드의 본문은 한 글자도 바꾸지 않는다.

## 측정 (2026-09-22, Claude)
외부(src+tests) 0회 & 내부 0회: `getStatistics`, `getStatusSummary`, `isProcessing`, `logDebugInfo`, `resetStatistics`, `startAutoCleanup` (6개).
내부에서만 참조되는 메서드 중 **위 6개에서만** 호출되는 것들도 연쇄적으로 dead: 후보 `getDebugInfo`(logDebugInfo만), `getSuccessRate`(getStatistics/getStatusSummary만), `getActiveProcessingCount`(getStatusSummary만), `cleanup`(startAutoCleanup만). **각 후보의 호출처를 grep으로 재확인한 뒤** 제거.

## 절대 규칙
- 제거 대상 외 코드 수정 금지. `safeReply/safeUpdate/safeShowModal/safeDeferReply/safeDeferUpdate/createErrorResponse/validateInteraction/startProcessing/finishProcessing/handleInteractionError` 및 이들이 부르는 헬퍼는 본문 불변.
- `this.statistics` 필드와 `updateResponseTimeStatistics` 는 **남긴다** (safeReply 본문이 쓰므로; getter만 dead인 상태는 후속 태스크에서 판단).
- `src/utils/SafeInteraction.js` 외 `src/**` 수정 금지.
- 삭제 판단 절차: 대상 메서드 이름으로 `grep -rn "<name>\b" src tests` → 정의 줄과 (삭제될) 다른 dead 메서드 안의 호출만 나오면 삭제. 하나라도 살아있는 호출이 있으면 남기고 보고.

## 테스트 (신규 `tests/utils/SafeInteraction.test.js`, 최소 6개)
- `validateInteraction`: 유효한 mock 인터랙션 → `{valid:true}`, `null` → `{valid:false, ...}` (구현 확인), 만료(createdTimestamp가 오래된 값) → valid false.
- `startProcessing` 같은 인터랙션 2회 → 두 번째 false; `finishProcessing` 후 다시 true.
- `safeReply`: 이미 `replied`이고 `editReply`가 있는 mock → `editReply`가 호출됨(구현의 분기 확인해 실제 동작대로), `deferred`면 `editReply`, 아니면 `reply`.
- `createErrorResponse(context, error)` 반환 객체 형태.
- `safeDeferUpdate`: mock의 `deferUpdate`가 호출되고 결과 반환.
