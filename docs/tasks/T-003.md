# T-003 husky pre-commit 훅

상태: done
계획: docs/IMPROVEMENT_PLAN.md §T-003

## 목표 (한 문장)
커밋 시 `lint` + `docs:check:strict` + `test`가 자동 실행되어 실패하면 커밋이 막히되, Termux prod(`git pull`만 하는 환경)에는 아무 영향이 없다.

## 범위
- 신규: `.husky/pre-commit` (내용: 아래 3줄)
  ```sh
  npm run lint
  npm run docs:check:strict
  npm test
  ```
- 수정: `package.json` scripts에 `"prepare": "husky || true"` 추가 (husky 미설치·CI·Termux에서 prepare 실패로 `npm install`이 깨지지 않도록 `|| true` 필수)
- husky 9.x는 이미 devDependencies에 설치됨. npm install 불필요(네트워크 불가). `npx husky` 로 `.husky/_` 초기화만 하면 됨.
- **건드리지 말 것**: `src/**`, `.husky/_/**` 는 husky가 생성하는 파일이므로 수동 편집 금지 (이미 `.gitignore`에 있는지 확인, 없으면 `.husky/_` 추가)

## 단계
1. `package.json`에 `prepare` 스크립트 추가.
2. `npx husky` 실행 → `.husky/_` 생성 확인.
3. `.husky/pre-commit` 작성 (shebang 없이 3줄만, husky 9 스타일). 실행 권한은 git이 관리하므로 `git add --chmod=+x .husky/pre-commit` 는 불필요, 단 Windows에서 생성 시 `git ls-files -s .husky/pre-commit` 모드가 100755 가 아니면 `git update-index --chmod=+x .husky/pre-commit`.
4. 검증: 훅이 실제로 도는지 — 임시 파일 `tmp-hook-test.js`에 `import x from './nope'` (확장자 누락 → lint error) 를 `src/`에 만들고 `git add` 후 `git commit -m test` 가 **실패**하는지 확인. 확인 후 임시 파일 삭제·unstage. (실제 커밋을 남기지 말 것)
5. `git status` 에 `.husky/_` 가 나타나지 않는지 확인.
